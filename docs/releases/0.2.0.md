Autobile 0.2.0 closes privacy and protected-screen gaps found during a release-gate audit.

## Upgrade notice

The 0.1.0 signing key was not retained in repository or CI custody. Android therefore
cannot accept 0.2.0 as an in-place update over 0.1.0. Uninstall 0.1.0 before installing
this release; uninstalling removes locally learned automations and history.

Starting with 0.2.0, the release key is held by GitHub Actions secrets and every tagged
release is built through the checked-in workflow. The certificate fingerprint printed
below is the stable baseline for subsequent updates.

## Security and privacy

- Cloud credentials are AES-GCM encrypted by Android Keystore. Existing 0.1.0 plaintext
  settings are encrypted on first use.
- Password fields are excluded from semantic screen context and demonstration traces.
  A recording containing secret input is rejected rather than embedding the value.
- Sensitive accessibility regions are painted over before a screenshot can reach any
  inference provider.
- Cloud endpoints must use HTTPS and credential entry is concealed in settings.

## Reliability

- Secure-window refusal is distinguished from permission, throttling, invalid-window,
  display, and internal screenshot failures.
- A vision-dependent step blocked by Android screen protection ends as `BLOCKED`; it is
  not treated as a recoverable UI mismatch and is never reported as complete.
- Continuous integration now builds and shrinks the release variant for every pull request.

## Documentation

- Added an architecture guide covering execution tiers, module boundaries, trust
  boundaries, persistence compatibility, and Android background limits.
- Added an explicit limitations section and a Keep a Changelog release history.
