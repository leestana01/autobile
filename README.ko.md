# Autobile

[English](README.md) · **한국어**

Autobile은 기기에서 먼저 판단하는 Android 자동화 에이전트입니다. 평소 하던 작업을
휴대폰에서 한 번 직접 보여주면, 무엇을 이해했는지 확인한 뒤 그 자동화를 수동으로,
정해진 시각에, 또는 특정 알림이 왔을 때 다시 실행할 수 있습니다.

런타임은 언제나 처리 가능한 가장 작은 실행 경로를 고릅니다. 먼저 결정적인 접근성
동작을 시도하고, 그다음 기기 내 추론, 선택적으로 설치한 로컬 모델, 마지막으로
사용자가 명시적으로 켠 클라우드 공급자 순입니다. 중요한 동작은 결정적 위험 정책이
검사하며, 의미 있는 모든 단계는 실행 후 화면과 대조해 검증합니다.

## 구현된 기능

- 고정 좌표가 아니라 화면 요소의 이름과 의도를 대상으로 삼는 의미 기반 자동화
- 접근성 트리 인식, 스크린샷, 노드 동작, 제스처, 앱 실행
- 기기 역량을 반영한 모델 라우팅, 기기 내 전용 요청 강제, 상위 전환 사유 기록
- 시연 기록, 불필요한 동작 정리, 의도 확인, 컴파일, 재실행
- 단계별·최종 목표 검증, 횟수가 제한된 복구, 수리 제안, 버전 이력
- 수동·시간·알림 트리거 및 재부팅 후 일정 복원
- 앱별 정책, 자율성 수준, 전체 정지 스위치, 민감 정보를 가린 이력, 지표
- Compose 기반 온보딩, 자동화 관리, 실행 이력, 설정, 위험 동작 확인 대화상자

## 요구 사항

- Android SDK 36이 설치된 Android Studio
- 로컬 빌드 및 Robolectric 테스트용 JDK 21
- Android 11(API 30) 이상을 실행하는 기기 또는 에뮬레이터

기기 내 생성형 기능은 해당 기기가 제공하는 모델 지원 범위에 따라 달라집니다.
Autobile은 실행 시점에 지원 여부를 확인하며, 사용할 수 있는 모델이 없어도 이미
저장된 결정적 자동화는 그대로 동작합니다.

## 빌드

`local.properties`에 `sdk.dir`을 지정하거나 `ANDROID_HOME`을 설정한 뒤 실행합니다.

```bash
./gradlew assembleDebug
```

디버그 APK는 `app/build/outputs/apk/debug/app-debug.apk`에 생성됩니다.

## 테스트

```bash
./gradlew test
```

Android에 의존하는 단위 테스트에는 Robolectric을 사용합니다. JDK 21을 사용하세요.
고정된 Robolectric 버전이 그보다 최신 JDK를 지원하지 않을 수 있습니다.

## 모듈 구조

```text
app/       Compose UI, 온보딩, 의존성 구성, 사용자 설정
core/      도메인 모델, 프라이버시를 고려한 저장소, 정책, 이력, 지표
ai/        공급자 중립 추론 인터페이스, 런타임 라우터, 범위가 한정된 작업
runtime/   접근성, 인식, 실행, 검증, 복구, 트리거
```

모듈 의존성은 의도적으로 안쪽을 향합니다. `app`이 프로세스를 조립하고, `runtime`이
에이전트 루프를 소유하며, `ai`가 추론 경계를 담당하고, `core`는 둘 중 어느 쪽에도
의존하지 않습니다.

## 권한과 프라이버시

Autobile은 Android 설정 화면을 열기 전에 각 권한이 왜 필요한지 먼저 설명합니다.

- 접근성 권한은 현재 화면을 읽고 조작하는 데 사용합니다.
- 알림 접근 권한은 알림으로 시작되는 자동화에만 필요합니다.
- 다른 앱 위에 표시 권한은 진행 상태 배너와 터치 표시를 위해 사용합니다.

클라우드 보조 기능은 기본적으로 꺼져 있습니다. 텍스트 전송과 스크린샷 전송은 서로
다른 동의 항목으로 분리되어 있으며, 전송이 허용된 요청이라도 기기를 떠나기 전에
스크린샷은 잘라내고 민감한 텍스트는 가립니다. 비밀번호 관리자와 인증 앱은 기본적으로
차단되고, 분류되지 않은 앱은 실행 전에 확인을 요구합니다.

## 배포에 관한 참고

Android 접근성 정책과 스토어 규정은 시간이 지나며 바뀝니다. 다른 앱을 넘나들며 작업을
계획하고 수행할 수 있는 빌드를 공개하기 전에 현재 배포 정책을 확인하세요. 전체 런타임을
포함한 빌드라면 일반 스토어 등록보다 비공개 테스트나 직접 배포 채널이 더 적합할 수
있습니다.

## 기여

변경 사항은 공급자 중립적이고 의미 기반이어야 합니다. 새로운 동작을 추가할 때는 검증,
실패 시 사용자 경험, 위험 검토, 그리고 기능을 지원하는 기기와 지원하지 않는 기기 양쪽에
대한 테스트가 함께 필요합니다. 자격 증명, 학습된 사용자 데이터, 스크린샷, 로컬 모델
파일, `local.properties`는 절대 커밋하지 마세요.
